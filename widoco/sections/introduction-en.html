Introduction back to ToC

The BIM Collaboration Format (BCF) links issues to building models without storing the models. bcfOWL represents BCF in RDF. It does not translate the BCF schema one to one. It composes BCF from established vocabularies and keeps only the concepts that are specific to BCF coordination.

BCF is an open standard of buildingSMART. It has two technical parts: the BCF-XML file format, which exchanges issues as files, and the BCF API, a REST interface for issue servers. See also the BCF overview at buildingSMART. bcfOWL covers the data model that both parts share.

A photograph, a camera pose, or a damage record can therefore exist in the graph without a BCF context. A BCF Topic or Viewpoint can refer to it later. If the BCF statements are removed from the graph, the referenced resources stay describable with the generic vocabularies alone.

The structural rules of BCF (for example, that a Topic has exactly one title) are not OWL axioms in this ontology. They are in a separate SHACL profile, bcfOWL-shapes, which checks a dataset under the closed-world assumption.

Previous version

Version 1.0.0 uses the namespace https://w3id.org/bcfOWL#. The last published version, 0.7.1 (2022-03-16), uses the namespace http://lbd.arch.rwth-aachen.de/bcfOWL#. Its documentation is at lbd.arch.rwth-aachen.de/bcfOWL_V1 (DOI 10.5281/zenodo.4710742). Data that uses the 0.7.1 terms needs a migration, because later versions removed and renamed terms. The changes and a migration table are in the change log.
